## Primitive locations under .apm/
| Primitive | Path |
|---|---|
| Skill | `.apm/skills/<name>/SKILL.md` + optional `scripts/`, `references/`, `assets/`, `examples/` |
| Agent | `.apm/agents/<name>.agent.md` |
| Prompt / command | `.apm/prompts/<name>.prompt.md` |
| Instructions | `.apm/instructions/<name>.instructions.md` |
| Hooks | `.apm/hooks/<name>.json` (+ scripts in a sibling folder) |

All Markdown primitives: UTF-8; if frontmatter is used, `---` must be the first content on line 1.

## Skill format
```
---
name: <skill-name>        # lowercase letters, digits, hyphens; 1-64 chars; no leading/trailing/double hyphens; must equal folder name
description: Use when ... # what + when; runtimes use it to decide when to invoke; <= 1024 chars
---
<instructions; "LOAD references/<file>.md" convention for extra material>
```
- APM copies the **whole skill folder** (scripts/, references/, assets/, examples/) to each target. Symlinks are filtered out.
- Keep SKILL.md < 500 lines / ~5000 tokens; move overflow to `references/`.
- No guidance on script dependencies → we use Python stdlib only.
- Validate: `apm audit --file .apm/skills/<name>/SKILL.md`

## Agent format (.agent.md)
```yaml
---
name: incident-analyst      # optional, defaults to file stem (stripped for kiro)
description: ...            # REQUIRED
model: ...                  # optional
tools: ...                  # optional whitelist
---
<persona and instructions>
```
- Kiro target: deployed to `.kiro/agents/<stem>.md`; keeps `description`, `model`, `tools`; strips `name` and unknown keys.
- Kiro `tools` values must be capability tags: `read`, `write`, `shell`, `web`, `subagent`, `knowledge`, `context`, `todo_list`, `@mcp`, `@builtin`, `*`. **Fail-closed:** any unsupported tag → agent not deployed. We use read, write, shell.
- VERIFY exact `tools` syntax (list vs map) with `apm install --dry-run --target kiro`.

## Prompt format (.prompt.md)
```yaml
---
description: ...
argument-hint: "[logs-path]"
input:
  - name: logs
    description: Path to log file or folder
---
Body uses $logs etc.
```
- Kept keys: `description`, `allowed-tools`, `model`, `argument-hint`, `input`. Others (author, parameters, mcp) are dropped with a diagnostic.
- Kiro target: deployed to `.kiro/prompts/<name>.md`. VERIFY whether Kiro IDE exposes these as slash commands (skills are confirmed slash commands).

## Hooks
- JSON keyed by event, Claude-style `{"hooks": {"PreToolUse": [{"hooks": [{"type": "command", "command": "...", "timeout": 10}]}]}}` or the "naked" form without the `hooks` wrapper.
- Events: SessionStart, Stop/agentStop, UserPromptSubmit, PreToolUse, PostToolUse, subagentStop, sessionEnd, postToolUseFailure, preCompact.
- Paths: `${PLUGIN_ROOT}` (also `${KIRO_PLUGIN_ROOT}`) = installed package root; `./x` resolves relative to the hook file. Scripts in a hook directory are deployed as a bundle.
- Kiro target: each hook action becomes its own file under `.kiro/hooks/`.
- Blocking / exit-code semantics are NOT documented → don't rely on hooks to block reads; enforce in the workflow skill.

## Publish to internal portal (confirmed)
- Repo is on internal GitLab. No CI pipeline in GitLab or portal.
- Publishing = push with tag + portal publishing form (name, description, category, tags, business line).
```
git add .
git commit -m "vX.Y.Z ..."
git tag vX.Y.Z               # matches apm.yml version
git push origin main --tags
```
- New release: bump `version` in apm.yml, new tag, push. Never move or delete an existing tag.
- Normal work commits: push without a tag.
